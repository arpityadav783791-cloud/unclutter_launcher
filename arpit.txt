5. APPLICATION ARCHITECTURE & DESIGN PATTERNS
====================================================================================================
- Architecture Pattern: MVVM (Model-View-ViewModel) + Single Activity Multi-Fragment Navigation
- Main Architecture Components:
  1) MainActivity: Hosts NavHostFragment, global message dialog overlays, orientation management,
     and broadcast receivers for profile changes and shortcut lifecycle updates.
  2) MainViewModel: Central state holder inheriting from AndroidViewModel. Exposes LiveData and
     SingleLiveEvent streams for app list updates, home screen reloads, alignment events, dialog
     triggers, and Private Space toggles.
  3) BaseFragment: Abstract base class providing custom onCreateAnimator overrides to cancel fragment
     animations when running on E-Ink devices or when system animations are turned off.
  4) HomeFragment: Primary interface rendering time, date, battery status, screen time, and 0-8 home apps.
  5) AppDrawerFragment: Recycler-based list containing searchable apps, private space section, and
     filtering mechanism.
  6) SettingsFragment: Detailed preference control panel with scrollable settings list.

- Communication Channels:
  * SingleLiveEvent<T>: Specialized LiveData implementation using AtomicBoolean(false) to ensure events
    (dialog triggers, home resets) are consumed exactly once by only one active observer.
  * MutableLiveData<T>: State holders for asynchronous background data (apps list, alignment, screen time).

8.1. HOME SCREEN SUBSYSTEM (HomeFragment.kt, OnSwipeTouchListener.kt, ViewSwipeTouchListener.kt)
----------------------------------------------------------------------------------------------------
- UI Layout: fragment_home.xml
- Functional Capabilities:
  1) Home App Slots: Supports between 0 and 8 user-defined apps or pinned shortcuts.
     - Tapping launches the target app or shortcut via ViewModel.
     - Long-pressing opens the App Drawer filtered for slot assignment with rename option.
     - D-pad accessibility: Each TextView is explicitly android:focusable="true".
  2) Time & Date Display:
     - Uses TextClock for current time (format: "h:mm").
     - Date format: "EEE, d MMM" (Locale formatted).
     - When status bar is hidden, the battery level percentage is appended to the date string:
       e.g., "Thu, 4 Sep, 85%".
     - Long-pressing Clock opens app picker to set a custom Clock app; tapping opens current/system clock.
     - Long-pressing Date opens app picker to set a custom Calendar app; tapping opens current/system calendar.
  3) Screen Time Display:
     - Queryable on Android 10+ (API >= 29) if PACKAGE_USAGE_STATS permission is granted.
     - Formatted as "Xh Ym", "Xm", or "<1m".
     - Tapping opens Digital Wellbeing (supports Google Digital Wellbeing and Samsung Forest Wellbeing)
       or custom assigned app. Long-pressing allows assigning a custom screen time app.
  4) Alignment Engine:
     - Horizontal Gravity: START (Left), CENTER, or END (Right).
     - Vertical Gravity: CENTER_VERTICAL (default) or BOTTOM (HomeBottomAlignment).
  5) Gesture Architecture:
     - OnSwipeTouchListener attached to root FrameLayout.
     - ViewSwipeTouchListener attached to each of the 8 home app TextViews.
     - Velocity and swipe thresholds: SWIPE_THRESHOLD = 100px, SWIPE_VELOCITY_THRESHOLD = 100px/s.
     - Gestures Supported:
       * Swipe Up -> Opens App Drawer (Constants.FLAG_LAUNCH_APP).
       * Swipe Down -> Notifications Drawer (via StatusBarManager reflection) or Web Search.
       * Swipe Left -> Configurable application (defaults to MediaStore.INTENT_ACTION_STILL_IMAGE_CAMERA).
       * Swipe Right -> Configurable application (defaults to Intent.ACTION_DIAL).
       * Double Tap -> Screen lock (via Accessibility Service or DeviceAdmin).
       * Long Press -> Opens SettingsFragment.
       * Single Tap -> Invokes periodic message checker (checkForMessages).

8.4. USAGE STATS & DIGITAL WELLBEING ENGINE (EventLogWrapper.kt, UnmatchedCloseEventGuardian.kt)
----------------------------------------------------------------------------------------------------
- Problem Solved: Android UsageStatsManager often drops close events, swaps events out of chronological
  order, or fails to report background transitions accurately across reboots and multi-window scenarios.
- Solution: Custom implementation ported from usageDirect library.
- Processing Pipeline:
  1) Queries ActivityManager.runningAppProcesses to capture currently visible and foreground packages.
  2) Queries UsageStatsManager.queryEvents between midnight (or start) and now.
  3) Handles Android Event Types:
     - ACTIVITY_RESUMED / 4 (CONTINUE_PREVIOUS_DAY) -> Records open timestamp in moveToForegroundMap.
     - ACTIVITY_PAUSED / ACTIVITY_STOPPED / 3 (END_OF_DAY) -> Matches open event and records foreground span.
     - DEVICE_STARTUP -> Clears pending open events, resetting query start.
     - DEVICE_SHUTDOWN -> Closes all active open events at shutdown timestamp.
  4) UnmatchedCloseEventGuardian:
     - If an unmatched close event is detected, Guardian scans backward up to 24 hours (SCAN_INTERVAL)
       to verify if the app was previously opened before the current query period began.
  5) Interval Merging: mergeOverlappingIntervals merges overlapping or concurrent component timestamps
     from the same package to avoid double-counting active time.

8.5. DAILY WALLPAPER & WORKMANAGER SUBSYSTEM (WallpaperWorker.kt, Utils.kt)
----------------------------------------------------------------------------------------------------
- Scheduled using Android Jetpack WorkManager:
  * Unique Periodic Work: Constants.WALLPAPER_WORKER_NAME
  * Repeat Interval: 4 Hours
  * Backoff Criteria: Linear, 1 Hour
  * Constraints: Requires NetworkType.CONNECTED
- Remote Wallpapers Source:
  * Curated JSON repository maintained by Tanuj:
    https://gist.githubusercontent.com/tanujnotes/85e2d0343ace71e76615ac346fbff82b/raw
  * Indexing algorithm:
    - If user installed < 10 days ago: uses install-relative index "0_{daysSinceInstall}"
    - If user installed >= 10 days: uses calendar month and day "{month}_{day}" (e.g. "9_4")
  * Separate keys for light and dark wallpapers.
  * Fallbacks: Curated Unsplash photos (Constants.URL_DEFAULT_DARK_WALLPAPER, URL_DEFAULT_LIGHT_WALLPAPER).
- Image Processing & Aspect Ratio Scaling:
  * Downloads raw stream via HttpURLConnection.
  * Queries display real dimensions using WindowManager.defaultDisplay.getRealSize(point).
  * Calculates widthScale and heightScale to take the max scale factor.
  * Centers and scales bitmap via Matrix transformation (preScale + postTranslate) on a Canvas.
  * Sets bitmap on WallpaperManager.FLAG_SYSTEM and WallpaperManager.FLAG_LOCK simultaneously.
  * Immediately recycles source and scaled bitmaps to prevent OOM memory leaks.

8.6. E-INK HARDWARE DETECTION & SPECIALIZED ENGINE (BaseFragment.kt, Extensions.kt, Utils.kt)
----------------------------------------------------------------------------------------------------
- Comprehensive E-Ink Detection Pipeline:
  1) Display Refresh Rate: Checks if max supported display refresh rate is <= 30Hz
     (windowManager.defaultDisplay.supportedModes.maxOf { it.refreshRate } <= 30f).
     * Note: Uses max supported refresh rate to prevent false positives on modern LTPO/adaptive displays
       that drop down to 1Hz-10Hz when idling.
  2) Onyx Boox Detection:
     - Checks Build.MANUFACTURER == "ONYX".
     - Attempts reflection check for Onyx proprietary SDK class: Class.forName("android.onyx.ViewUpdateHelper").
  3) Dedicated E-Ink Brands List:
     - Inspects Build.BRAND and Build.MANUFACTURER for:
       "onyx", "boox", "dasung", "bigme", "boyue", "meebook", "mudita".
  4) Hisense E-Ink Lineup Detection:
     - Regex match for "\bA[579]\b|TOUCH|HI READER" against Build.MODEL.
- E-Ink Specific Optimizations Applied:
  * Forces Light Theme (AppCompatDelegate.MODE_NIGHT_NO) with pure white background.
  * Sets plain white wallpaper on launcher setup.
  * Cancels all Fragment entry and exit animations (ValueAnimator.ofFloat(0f, 1f).setDuration(0)).
  * Sets RecyclerView overscroll mode to View.OVER_SCROLL_NEVER (prevents ghosting artifacts).
  * Replaces alpha animations with instantaneous view.alpha assignments.

8.7. PINNED SHORTCUTS & PWA SUPPORT (ShortcutIdentity.kt, PinItemActivity.kt)
----------------------------------------------------------------------------------------------------
- Android Pinned Shortcuts Integration:
  * Queries LauncherApps.ShortcutQuery with FLAG_MATCH_PINNED.
  * Generates collision-proof composite identity via shortcutIdentity():
    Format: "shortcut:{pkgLen}:{pkg}{idLen}:{id}{userLen}:{user}"
    Example: "shortcut:15:org.mozilla.fenix22:https://news.ycombinator.com13:UserHandle{0}"
  * Supports dynamic shortcuts, PWA home screen shortcuts (Chrome, Firefox, Brave), contact shortcuts.
  * PinItemActivity handles incoming system shortcut requests (REQUEST_TYPE_SHORTCUT) and calls pinItemRequest.accept().
  * Deletion: Context.deletePinnedShortcut re-pins remaining shortcuts using LauncherApps.pinShortcuts.

8.8. ANDROID 15+ PRIVATE SPACE SUBSYSTEM (MainViewModel.kt, AndroidManifest.xml, Utils.kt)
----------------------------------------------------------------------------------------------------
- Supports Android 15 (Vanilla Ice Cream / API 35+) Private Space profiles:
  * Uses android.permission.ACCESS_HIDDEN_PROFILES.
  * Detects profile user type: launcherApps.getLauncherUserInfo(userHandle)?.userType == "android.os.usertype.profile.PRIVATE".
  * Profile Availability Receiver: Listens for Intent.ACTION_PROFILE_AVAILABLE and ACTION_PROFILE_UNAVAILABLE.
  * State Tracking: Queries UserManager.isQuietModeEnabled(handle) to check locked/unlocked state.
  * Unlocking / Locking: Invokes userManager.requestQuietModeEnabled(!currentlyLocked, handle)
    which triggers system biometric / PIN confirmation.
  * UI Integration: Shows a dedicated "Private space" header in app drawer. Tapping toggles lock/unlock;
    long-pressing launches system Private Space settings.
  * Safety: Maintains flag `isPrivateSpaceToggling` to prevent popping back to home screen while the OS
    shows the biometric credential authentication sheet.

8.9. ACCESSIBILITY SERVICE & DEVICE ADMIN (Lock Screen Engines)
----------------------------------------------------------------------------------------------------
- Two distinct screen locking mechanisms depending on Android API level:
  1) Android Pie+ (API >= 28): MyAccessibilityService
     - Isolated process: android:process=":serviceProcess".
     - Listens for accessibility event on an invisible 1dp FrameLayout in HomeFragment with
       contentDescription == @string/lock_layout_description.
     - Calls performGlobalAction(GLOBAL_ACTION_LOCK_SCREEN).
     - Does not compromise biometric unlock (Smart Lock and fingerprint remain available).
  2) Legacy Android (API < 28): DeviceAdmin
     - Binds DevicePolicyManager with uses-policies <force-lock />.
     - Calls deviceManager.lockNow().

11. BUGS, ANOMALIES, TECHNICAL DEBT & VULNERABILITIES AUDIT
====================================================================================================
During this comprehensive code audit, the following specific bugs, code smells, and technical debt
items were uncovered:

1) Bug in DeviceAdmin.kt (Lines 15-18):
   - In onDisabled(intent: Intent?, context: Context), the toast displayed is:
     Toast.makeText(context, context.getString(R.string.enabled), Toast.LENGTH_SHORT).show()
   - Anomaly: It displays "Enabled" when the device admin is actually *disabled*. It should be R.string.disabled.

2) Non-Existent Settings Activity in accessibility_service_config.xml (Line 10):
   - Attribute specifies: android:settingsActivity="com.example.android.accessibility.ServiceSettingsActivity"
   - Anomaly: This is a placeholder copied from Android sample code. Tapping "Settings" on the Accessibility
     page in system settings will crash or fail silently because this activity does not exist in Olauncher.

3) GlobalScope Coroutine Launch in Touch Listeners (OnSwipeTouchListener.kt & ViewSwipeTouchListener.kt):
   - Uses GlobalScope.launch { delay(500); ... } for long-press handling.
   - Anomaly: GlobalScope usage is discouraged in modern Kotlin as it breaks structured concurrency and
     can leak coroutines beyond the view lifecycle.

4) Deprecated / Commented-out "Home Button For Recents" Feature:
   - Residual code exists across AndroidManifest, MainActivity, HomeFragment, SettingsFragment,
     strings.xml, and MyAccessibilityService for a "Home button for recents" feature that is disabled.

5) SingleLiveEvent Multiple Observers Warning:
   - SingleLiveEvent logs a warning if multiple observers attach, but does not enforce a single observer
     at compile time. MainViewModel exposes SingleLiveEvents that could miss events if lifecycle owners reattach.

6) Target SDK 36 Bleeding Edge:
   - Target SDK is set to 36 (Android 16), which is higher than standard stable release targets (SDK 34/35).
   - android.suppressUnsupportedCompileSdk=34 is present in gradle.properties to bypass build tooling warnings.
